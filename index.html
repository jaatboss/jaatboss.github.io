Machine learning · deep learning · LLM systems

Five AI/ML projects, each evaluated and documented, with the limitations stated.

The projects cover graph neural networks, recurrent NLP models, calibrated tabular classification, tool-using LLM agents and retrieval-augmented generation. Each started from a public tutorial and was then extended with a research interface, a re-evaluation of the shipped model or pipeline, and a written account of what the results do and do not show.

Graph neural networks · node classification

GraphMind: topic classification on the Cora citation graph

A two-layer graph convolutional network labels 2,708 papers with one of seven topics, using each paper's word features and its citation links. The model runs in ONNX Runtime behind FastAPI.

What was added and what the results show
  • Interactive 1- and 2-hop citation-neighbourhood graph, built from the real Cora edges.
  • Edge-ablation experiment: the same model with every citation replaced by a self-loop drops from 0.792 to 0.678 accuracy, which quantifies what message passing adds.
  • Live evaluation of the exported model: confusion matrix and per-class metrics.
  • Limitations noted: one training run with no seed variance; the exported weights are from the final epoch rather than the best one (because of how the notebook saved its checkpoint); training accuracy is 1.000 (overfitting); the setting is transductive.

Natural language processing · recurrent networks

Moodalyx: emotion-label prediction with a bidirectional GRU

A stacked BiGRU (3.45 M parameters) trained on dair-ai/emotion predicts one of six labels for short English text. It reports the full probability distribution and shows the cleaned tokens the model actually reads.

What was added and what the results show
  • Re-evaluation script that scores the shipped model on the 2,000-sentence test split through the API's own preprocessing; it reproduces the notebook's 0.921.
  • Confusion matrix, reliability diagram, per-label metrics and the most confident errors.
  • Batch comparison mode; flags when the top two labels are close or when input is longer than the model reads.
  • Limitations noted: the test split was also used for early stopping, so the score is optimistic; there is no neutral class; the domain is narrow; the output is a dataset-label prediction, not a measure of anyone's emotional state.

Tabular ML · probability calibration

CreditCompass: calibrated loan-default probability with XGBoost

An XGBoost pipeline, tuned by randomized search and wrapped in sigmoid calibration, estimates default probability from 11 application features. Each estimate is shown next to the default rate actually observed among held-out applicants with similar scores.

What was added and what the results show
  • Reproduced the notebook's exact stratified split (6,305 test rows) and re-scored the shipped calibrated model.
  • Threshold explorer, PR/ROC curves, calibration curve and permutation importance.
  • Sensitivity tool that varies one input and queries the real model at each value.
  • Limitations noted: the notebook's threshold search used an incorrect F1 formula and the test set; mid-range probabilities are over-confident; lender-assigned grade and interest rate are inputs; no fairness audit. This is not a lending tool.

Agentic AI · tool-using LLM agents

Scholaryx: a sequential multi-agent research pipeline

A search agent (Tavily), a reader agent (web scraping), a writer chain and a critic chain turn a topic into a structured report with a self-critique. The workbench shows each stage live, along with the measured cost.

What was added and what the results show
  • Replaced the Streamlit UI with a FastAPI server that calls the original pipeline unchanged, with live stage tracking.
  • Token and cost measurement via LangChain's OpenAI callback.

Approach

Re-evaluate the shipped artifact

Metrics come from the saved model files, scored on the original splits, rather than being copied from a single notebook run.

Show the evidence

Interfaces display probability distributions, retrieved passages, confusion matrices and calibration curves, not just a single label.

State the limitations

Each project lists known issues found during review, such as data leakage, checkpointing bugs and an incorrect threshold formula, including the ones not yet fixed.

How these were built

Each project began from a public YouTube tutorial, which provided the original model or pipeline code. On top of that, the work shown here adds: research interfaces in HTML, CSS and JavaScript (replacing Streamlit where it was used); re-evaluation of the saved models; error and calibration analysis; bug investigation (the vector-store fix in the video project); and written documentation of limitations. The core model and pipeline code comes from those tutorials; each repository's README describes what was added on top.
